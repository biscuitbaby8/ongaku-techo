# AdSense 再不承認（2026-08）の原因調査

調査日: 2026-08-20 / 対象: 本番 `https://ongakutecho.com`（デプロイ 2026-08-19 19:56 時点）
前回調査: `docs/adsense-improvement-plan.md`（2026-07-26 作成 / 07-29 追記）

---

## 結論

**前提が間違っていた。** 前回ドキュメントは「Phase 2（コンテンツの作り直し）は完了した。
全1,116語に1,100〜2,100文字の記事を書いた」としているが、`src/data/termArticles.js` を
実測すると **1記事あたりの独自本文は平均463文字・中央値450文字** で、
主張されている量の 1/3 以下しかない。

つまり前回「解決済み」とされた **2番目の原因（低品質・大量生成コンテンツ）は
解消されていない**。今回の不承認は、前回と同じ理由で落ちていると考えるのが自然。

「再クロールが追いついていないだけ」という前回の見立ては、この実測により否定される。
待っても状況は変わらない。

## 1. 【最重要】記事の分量が主張の 1/3 以下

`termArticles.js` の全1,116エントリについて、`lead` + `sections`(見出し+本文) +
`confusions` + `instruments` + `works` の文字数を合計した実測値。

| 指標 | 実測値 | ドキュメントの主張 |
|---|---|---|
| 平均 | **463文字** | 1,100〜2,100文字 |
| 中央値 | **450文字** | 〃 |
| 最短 | **134文字** | 〃 |
| 最長 | 1,134文字 | 〃 |

分布:

| 閾値 | 該当件数 | 割合 |

| 300文字未満 | 248件 | 22.2% |
| 400文字未満 | 473件 | 42.4% |

### なぜ「1,100〜2,100文字」という数字が出たのか

おそらく**ページ全体の可視テキスト**（ヘッダー・パンくず・関連用語8件・フッター等の
全ページ共通部分を含む）を数えている。ただしそれで数えても主張には届かない。
`dist/term/*/index.html` から `<script>` `<style>` `<head>` を除いて可視テキストを実測すると:

| 指標 | 実測値 |
|---|---|
| ページ全体の可視テキスト 中央値 | **925文字** |
| 同 最短 | 579文字 |
| 同 最長 | 1,634文字 |

つまり **ページ全体を数えても中央値925文字**で、そのうち約半分は全ページ共通の定型部分。
「各ページ1,100〜2,100文字超」という記述はどちらの数え方でも成立しない。

### 「厚い記事」のテンプレートが適用されているのは一部だけ

`/term/adagio/` のような、語源・演奏のヒント（楽器別）・混同しやすい用語・使われている曲まで
揃った構成は例外。フィールドの保有率は次のとおり。

| フィールド | 保有記事数 / 1,116 |
|---|---|
| `lead` | 1,116 (100%) |
| `sections` | 1,116 (100%) — ただし **1つ以下が248件** |
| `confusions` | 1,059 (95%) |
| `works`（使われている曲） | **175 (15.7%)** |
| `instruments`（楽器別のヒント） | **161 (14.4%)** |

**演奏のヒントも曲例もどちらも無い記事が 941件（84%）。**
`/term/adagio/` を見て「全ページこの厚さ」と判断すると実態を大きく取り違える。

## 2. 同義語ページが残っている

同一の `meaning` を共有する用語が **31グループ・68語** 残存している。
前回調査時点（35グループ・75件）からほぼ変わっていない。

```
「だんだん弱く」   → Decrescendo, Diminuendo, Abnehmend
「消えゆくように」 → Smorzando, Perdendosi, Diluendo
「少し、わずかに」 → Poco, Wenig, Un poco
「表情豊かに」     → Espressivo, Mit Ausdruck, Expressif
「だんだん遅く」   → Ritardando, Rallentando
「速く」           → Schnell, Geschwind
「遅く」           → Langsam, Lent
...
```

上の「最短15件」と見比べると分かるとおり、**最も薄いページ群 = この同義語・他言語訳語の
ページ群**。イタリア語版に本文を書き、ドイツ語版・フランス語版は「◯◯のドイツ語」で
1ページ立てる、という構造が残っている。

本文レベルの近似も検出した（4-gram Jaccard > 0.4 のペアが15組）:

```
angosciamento / angoscioso  0.66
furieusement  / furioso     0.65
accarezzevole / carezzevole 0.58
abbandonatamente / con-abbandono 0.57
dampfer-auf   / dampfer-ab  0.56
amabilmente   / amabile     0.54
```

完全一致する本文パラグラフも10種類20箇所ある。

## 4. 「大量生成コンテンツ」のパターンに合致している

Google は2024年3月のスパムポリシー改定で
「**大規模に生成されたコンテンツの不正使用**（scaled content abuse）」を明文化した。
判断されるのは「AIを使ったかどうか」ではなく「独自の価値が薄いページを大量に作っているか」。

現状は次のとおり、そのパターンに正面から当たる。

- 1,116ページが**完全に同一のテンプレート**（意味 → 解説 → セクション → 関連用語8件 → フッター）
- 独自本文は中央値450文字、22%が300文字未満
- 見出しも定型が多い（「語源」74回、「演奏上の要点」68回、「演奏上の判断」65回）
- 全ページが短期間に一括で公開されている（git履歴: 2026-07-27〜07-29 の数日で約1,100語分）
- **過去にクローキング（スパムポリシー違反）を実装していた履歴がある**
  （`61dd33d` / `60d2303`。前回調査で撤去済みだが、サイトの信頼度に影響している可能性は残る）

用語数1,116という規模は、この文脈では加点ではなく**減点方向**に働く。

## 5. 運営者情報の裏付けが無い

`public/about.html` に次の記述がある。

> 現役の奏者・講師の経験に基づいた「演奏現場で役立つ実用的な解説」を心がけています。
> ※このアプリは、現役の奏者や講師の監修を元に、biscuitbaby / ongaku-techo Project が運営しています。

トップページの `#seo-content` にも「現役の奏者や講師の監修を元に制作されています」とある。
しかし**執筆者・監修者の氏名も経歴も、サイトのどこにも書かれていない**。
審査側から見ると検証できない主張であり、E-E-A-T（専門性・権威性・信頼性）の観点では
むしろマイナスに働く。

- 実際に監修者がいるなら → 氏名・経歴・担当範囲を About に明記する
- いないなら → 記述を実態に合わせて書き換える（「独自に執筆」で十分）

あわせて About の「強弱、速度、奏法、表情、構成の5カテゴリ」という記述も誤り。
実際は形式・理論・楽器を含む**8カテゴリ**。

## 提案：次に何をするか

前回ドキュメントは「案A: 全ページを厚くする」を選んで実行したが、実測のとおり目標量に
届いていない。全1,116ページを800〜1,000字にするには残り40〜60万字の執筆が必要で、
やはり現実的ではない。**前回ドキュメント自身が推奨していた案B（ページを絞る）に切り替えるのが妥当。**

### 優先度1 — ページ数を絞る

1. `termsData.js` に `isFeatured: true` を持たせ、**主要150〜200語だけ**個別ページを生成する
   （`scripts/generate-static-pages.js` を1行分岐させるだけで実装できる）
   - 残す語の選定基準: 独自本文が長い順 + 検索需要のある基本用語
   - 現状 `works` と `instruments` の両方を持つ161語がほぼそのまま候補になる
2. 残り約900語は個別ページを廃止し、カテゴリ一覧ページ内の項目に格下げ。
   既存URLは `vercel.json` の `redirects` でカテゴリ一覧へ301リダイレクト
3. 残した150〜200語は、`/term/adagio/` と同じ厚さ（語源・楽器別のヒント・混同しやすい用語・
   使われている曲）まで揃える

### 優先度2 — 辞書以外のコンテンツを作る

4. カテゴリ一覧9ページに、そのカテゴリの全体像を解説する導入文（各1,500〜2,000字）を追加
5. 読み物としてのオリジナル記事を5〜10本追加（`/article/` 等）。例:
   - 強弱記号は「音量」ではない — p と pp の本当の違い
   - Andante と Adagio と Lento を混同しないための3つの基準
   - メトロノーム練習でやってはいけないこと
   - チューナーのセント表示の読み方
   - 速度用語をBPMに読み替える早見表

### 優先度3 — 信頼性・技術面

6. About の監修者記述を実態に合わせる（氏名・経歴を出すか、記述を外すか）。カテゴリ数の誤記も修正
7. ヘッダーの `SEARCH OPTIMIZED V8.0` を外す
8. `termsData.js` / `termArticles.js` を動的importに分割し、初回バンドル1.86MBを削減

### 再申請のタイミング

上記の優先度1・2を反映してデプロイ → Search Console でsitemap再送信とインデックス登録を
リクエスト → **2週間以上あけてから**再申請する。

**再申請の前に必ず AdSense の「サイト」「ポリシーセンター」を確認すること。**
具体的な違反種別が表示されていれば、この文書の推測よりそちらを優先する。
